# FIRST LIGHT site

Static site on Cloudflare (Workers assets). The landing page and privacy notice are hand-written
HTML at the repo root; everything under `/publications/` and `/index/` is generated by
`scripts/build.mjs`. No dependencies, no live backend. Needs Node 20+.

```
npm run preview       # build with fictional fixtures + drafts and serve at localhost:8765 (never deployed)
npm run build         # build for real into dist/
npm run new-private   # create data/private/<random-token>.json for a one-off page
npm run deploy        # build, then upload dist/ to the Cloudflare Pages project (firstlight.agency)
npm run refresh       # export from the Observatory, then deploy if the rankings changed
```

The site is a Cloudflare **Pages** project named `eminence` (it serves firstlight.agency). `wrangler.toml`
points at `dist/`, not the repo root, and deploys go up with `wrangler pages deploy`. Only the files listed in `STATIC` in
`scripts/build.mjs` are copied there, so a new root-level asset (image, video) has to be added to that
list. Everything else, including `data/`, `scripts/` and `apps-script/`, is not published.

## Routes

| Route | Source |
|---|---|
| `/index/` | Rankings. `data/index.json`; a "being compiled" placeholder if absent |
| `/index/winners-losers/` | Same file, `winners_losers` key. Not built if the key is absent |
| `/publications/` | generated from `content/publications/*.md`, with the manifesto pinned first |
| `/publications/<slug>/` | one per article; slug is the filename (`manifesto` and `private` are reserved) |
| `/manifesto/` | `templates.mjs` → `manifestoPage`, styled by `manifesto.css`. Placeholder copy for now. `/publications/manifesto/` 301s here |
| `/observatory/` | `templates.mjs` → `observatoryPage`, styled by `observatory.css`. Status line from `data/observatory-status.json` |
| `/publications/private/<token>/` | `data/private/<token>.json`, one page per file |

Articles: front matter `title`, `date`, `summary`, optional `type` (`article` or `case-study`) and
`draft: true`. Body is a small Markdown subset (`##`/`###`, lists, `>` quotes, images, links, bold, italic).
Files in `content/publications/<slug>/` are copied next to the article, for images.

## How the site gets its data

```
Observatory (Postgres, on the laptop)
   └─ observatory/site_export.py   read-only, allowlisted fields only
        └─ eminence/data/index.json
             └─ scripts/build.mjs → dist/ → wrangler deploy
```

`scripts/refresh-site.sh` (`npm run refresh`) runs the export and deploys when the file changed. Schedule it
with `scripts/com.firstlight.refresh-site.plist.example` (a launchd job; install steps are in the file). Setup,
once:

1. In Cloudflare, create an API token from the "Edit Cloudflare Workers" template and note the account id.
   Create the file `~/.config/first-light/env` (it does not exist until you make it: `mkdir -p ~/.config/first-light`
   then open the file in any editor) with two lines, `CLOUDFLARE_API_TOKEN=…` and `CLOUDFLARE_ACCOUNT_ID=…`, and
   run `chmod 600` on it. It lives outside the repo so the token never gets committed.
2. **Don't let Git deploy it.** The laptop is the only deployer, because it holds the private pages' data; a
   build from Git would replace the site without them. If a Git build does run, it fails on purpose
   (`CF_PAGES` set and no `data/index.json`) and the live site is untouched.
3. Install the launchd job.

The laptop has to be awake at the scheduled time (launchd runs a missed job on wake). If it is off, the site
just keeps its last data.

`data/index.json` is generated, so it is git-ignored.

`data/observatory-status.json` (`{"last_reading": "<ISO 8601>"}`) is written by the Observatory pipeline and
published as `/observatory-status.json`, which the `/observatory/` page reads for its "Last reading" line. It is
git-ignored too. If it is missing or not a valid timestamp, the build leaves it out and the page hides the line.
`npm run refresh` deploys when either file changed. It is rewritten only when the content changes.

### `data/index.json`

Written by the Observatory's exporter, validated by the build (which fails loudly on a malformed file).

```json
{
  "generated_at": "2026-09-24T00:00:00Z",
  "period": "Movement since 25 Aug 2026",
  "rankings": [{
    "division": "Lightweight", "rank": 1, "prev_rank": 3, "name": "…", "rating": 1842,
    "fli": 0.62,
    "fli_trend": { "dir": "up", "delta": 0.06, "days": 30 },
    "fli_history": [{ "date": "2026-08-25", "fli": 0.56 }, "…"]
  }],
  "winners_losers": {
    "period": "Fights from 25 Aug to 24 Sep 2026",
    "winners": [{ "name": "…", "outcome": "loss", "opponent": "…", "method": "Decision (Split)", "event": "…", "date": "2026-09-12", "change": 14.2 }],
    "losers":  [{ "name": "…", "outcome": "win", "…": "…", "change": -9.4 }]
  }
}
```

- `rating` is the FLR (First Light Rankings) rating; `fli` is the First Light Index, between -1 and 1.
- `prev_rank`: a number is last period's rank, `null` means not ranked then ("New"), and leaving the key out
  means nothing to compare with (the Move column is then hidden).
- `fli_trend` drives the 30-day ticker; `fli_history` (oldest first, 3+ points) drives the sparkline shown on hover.
  Both are optional per fighter.
- Divisions appear in the order the file lists them; each is collapsed to its top 3 on the page.
- `fli_status: "pending"` (instead of `fli`) means the FLI is withheld because a platform it rests on hasn't been
  checked; the page shows a "Pending" flag.
- Winners lost the fight but grew their audience far more than typical; losers won but grew it hardly at all.
  `change` is the fighter's audience change in percent, and the exporter sets the bar (winners at least 3x the
  typical post-fight change, losers at most a quarter of it), so the lists are short. The build only rejects a
  list whose results or signs contradict its heading.
- No follower counts, handles or ids are ever in this file.

## Private pages

`data/private/<token>.json`: see `data/sample/private/` for a full example. Blocks are `fighter`, `manager`,
`media` (`[{label, url, note}]`) and `notes`; use any of them. `title` shows in the browser tab and link
previews, so keep names out of it.

- The token is the whole address. `npm run new-private` makes 192 random bits once and stores it in the
  file, so rebuilds keep the URL stable. The build rejects tokens under 32 characters and tokens that contain
  the fighter's or manager's name. New files are created with `"draft": true` and skipped until you delete it.
- Nothing links to them, and the build enforces it: it fails if any output outside the private tree contains
  `publications/private` or any token. They are never added to `sitemap.xml`.
- Each page has `noindex, nofollow, noarchive`, `Referrer-Policy: no-referrer` (so the URL isn't sent to
  sites its links point at) and `no-store`. The headers come from the generated `_headers`; the meta tags
  are in the page itself.
- `robots.txt` deliberately has no `Disallow` for the path. It is public, so it would advertise the path,
  and a crawler that is blocked never reads the noindex tag.
- `data/private/` and `dist/` are git-ignored, so this data is never committed. Anyone with the link can open
  the page: don't put anything in one that would hurt if the link were forwarded.

## Site URL

`sitemap.xml` and canonical tags use `https://firstlight.agency`. Override with `SITE_URL=… npm run build`.
